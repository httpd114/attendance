# 派遣项目考勤异常双向确认系统 · 需求清单 v0.1

> 状态：骨架已确认（Q1/Q4/Q5/Q7），其余为架构师推荐默认，待客户最终确认。
> 版本：2026-10-30　|　角色：需求评审（十年企业 IS 架构经验）

---

## 1. 业务目标
- **一句话**：让"考勤异常"在派遣员工与用工单位管理员之间完成**可追溯的双向确认**，消除口头扯皮与责任不清。
- **核心价值**：异常不落地为确认记录 = 薪资/结算争议源头。系统把"谁在何时确认了哪个版本的异常"固化下来。
- **一期不追求**：自动算薪、自动开票、复杂申诉仲裁。

---

## 2. 范围边界
**范围内（In）**
- 考勤异常的**生成 → 员工确认/异议 → 管理员复核 → 关闭**全流程。
- 多租户（用工单位隔离）、全链路审计、脱敏导出。
- 异常数据**导出为结算清单**（不直接写薪资系统）。

**范围外（Out，一期不做）**
- 直连薪资/服务费结算、自动开票、报销触发。
- 设备直连（闸机/人脸 SDK）、实时事件总线。
- 复杂申诉工单、2×2 双向独立一致矩阵。
- 多活/容灾（二期）。

---

## 3. 关键设计决策（已确认 + 默认）

| 编号 | 决策项 | 结论 | 架构影响 |
|---|---|---|---|
| Q4 | 主体隔离 | **多租户，用工单位为租户边界**；派遣公司跨租户只读监管；员工仅本人数据 | 租户 ID 贯穿全表 + 行级隔离 + RBAC |
| Q5 | 部署 | **MVP SaaS 多租户试点；二期支持私有化交付包**（离线 License） | 云原生 K8s；二期预留私有化安装与离线认证 |
| Q1 | 确认语义 | **线性推进 + 员工可异议**；管理员复核为终态 | 状态机：待确认→员工确认/异议→管理员复核→已确认/已关闭 |
| Q7 | 结算边界 | **一期仅记录 + 导出结算数据**；不直连薪资、不开票 | 系统闭环，无下游强一致依赖 |
| Q2 | 数据源 | **默认：批量文件导入（Excel/CSV 打卡导出）+ 预留 API 适配器**；不做设备直连 | 定时 ETL + 文件解析；适配器接口预留 |
| Q3 | 规则可配 | **管理员可配置（元数据驱动）+ 规则版本快照**；不引规则引擎 | 规则配置界面 + 规则版本表（历史判定可回溯） |
| Q6 | 时限/超时 | **有时限（默认 3 工作日）+ 超时升级上报，绝不自动通过** | 定时扫描 + 升级通知（轻量，非全 BPMN） |
| Q8 | 触达入口 | **MVP：短信链接 + Web 确认（一次性令牌防冒领）**；二期按租户接企微/钉钉 | 短信网关 + 短链 + OTP；IM 集成放二期 |
| Q9 | 合规/审计 | **全链路审计（谁查哪条、哪版确认）+ 留存≥2 年 + 脱敏导出审批** | 不可篡改审计表 + 脱敏引擎 + 导出审批流 |
| Q10 | 规模/节奏 | **一期单客户 ≤2000 员工验证；架构按万级预留（读写分离/缓存）但不一期实现** | 单体 + 单库起步；预留分片与缓存点 |

> 标注「默认」的六项为用户授权架构师按合理实践填写，列为待决项（见 §6），客户确认后转为「已确认」。

## 4. 核心状态机（一期）
```
[异常生成] → (待确认)
   ├─ 员工确认 ──────────────┐
   └─ 员工异议 ─→ (复核中) ──┤
                              ↓
                  [管理员复核] → 确认/驳回
                              ↓
                        (已关闭 / 终态)
超时(3工作日未确认) → 升级上报用工单位管理员（不自动通过）
```

---

## 5. 非功能基线（一期目标）
- **安全**：租户间数据严格隔离；员工确认用一次性令牌，防冒领/重放。
- **合规**：考勤属个人信息，按《个保法》留痕 + 脱敏导出审批；留存≥2 年。
- **审计**：每次查看/确认/复核记录操作人、时间、数据版本，不可篡改。
- **性能**：≤2000 人单租户下，异常列表与确认操作 P95 < 1s；批量导入支持万行级。
- **可用**：一期单实例，目标 99.5%；多活/容灾二期。
- **可运维**：SaaS 自助开通 + 标准灰度升级；私有化二期提供离线升级包。

## 6. 待决项 / 开放问题
1. **Q2 数据源**：首个客户考勤数据实际格式？是否已有第三方 HR 接口可复用？
2. **Q3 规则**：各用工单位异常规则差异有多大？是否需要"规则按项目覆盖"？
3. **Q6 时限**：3 个工作日是否覆盖所有异常类型？超时升级到哪一级？
4. **Q8 触达**：员工是否普遍有手机号可用？企微/钉钉归属派遣公司还是用工单位？
5. **Q9 合规**：客户是否有指定留存年限 / 等保级别要求？
6. **Q10 规模**：试点客户实际员工数与项目数？是否有明确上线 deadline？
7. **跨项**：异议复核的时限与终裁人是否和管理员为同一角色？
