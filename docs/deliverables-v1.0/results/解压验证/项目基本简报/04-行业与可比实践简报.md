## 2. 政策与合规底线（官方来源）

| 要求 | 内容 | 出处 |
|---|---|---|
| 三性岗位 | 临时性（≤6 个月）、辅助性、替代性 | 《劳务派遣暂行规定》第 3 条 |
| 用工比例 | 被派遣劳动者 ≤ 用工总量 10% | 第 4 条 |
| 合同 | 2 年以上固定期限书面劳动合同 | 第 5 条 |
| 派遣协议 | 须载明岗位名称与性质、地点、人数与期限、报酬、社保、工时休假等 13 项 | 第 7 条 |
| 罚则 | 责令限期改正，逾期按每人 5000~10000 元罚款 | 《劳动合同法》第 92 条 |

公开执法案例：2025 年四季度内蒙古某电力安装分公司派遣占比 36.20% 被责令整改；2026 年 4 月东莞某企业用工 989 人、派遣 165 人超比例，逾期未改被罚 20.5 万元。

**对本项目的直接含义**：字段「岗位性质、工作地点、人数、期限、班次/工时、技能条件」不是普通业务字段，而是法定协议要素；AI 辅助结果一旦影响这些字段，必须有人确认与全量留痕，不得自动写回（对应 f32 只读导出、f42 验收、f45 审计）。

## 4. 可比技术实践（公开案例）

| 案例 | 做法 | 可借鉴的量化门禁 |
|---|---|---|
| Symphony Solutions 多 Agent HR 助手（2025-12 MVP） | SharePoint 文档 RAG + Qdrant 向量库，Entra ID 鉴权 + RBAC，LangGraph 编排，FastAPI 后端 | groundedness >90%（LLM-as-a-Judge）；ci 门禁 answer correctness ≥0.90、faithfulness ≥0.95；知识库更新 1 天内重索引 |
| 内蒙古电力「广智灵犀」 | 通义千问 / DeepSeek 本地部署 + RAG 本地知识库，覆盖岗位上岗条件、政策文件查询 | 局域网内私有化，知识不出域 |
| Oracle Fusion HR RAG Agent | 会话变量注入员工职级/部门等上下文，按人给差异化政策答复；JWT 鉴权 | 上下文受控 + 身份绑定 |
| AxtraLabs / FidelSoft HR 助手 | RAG + RBAC + 审计日志；明确 no-hallucination policy，回答只以官方知识库为据 | 拒答与来源约束优先于覆盖率 |

行业报告另给出：AI 招聘工具渗透率约 77%；HR 领域 AI 采纳率 2024-11 的 37.3% → 2026-05 的 47.9%，但仅 2.7% 达到规模化应用、5.5% 能以可衡量业务成果证明价值（行业报告口径，非官方统计）。

## 5. 本项目与可比实践的差异（关键，不得略过）

| 差异点 | 可比案例的前提 | 本项目现状 | 依据 |
|---|---|---|---|
| 统一关联编号 | 文档/记录有稳定 ID 可索引 | 需求单**无统一关联编号**，跨工具靠人工比对 | f30 |
| 写回与集成 | 常与 HRMS/ERP 实时集成 | 试点**仅脱敏只读导出**，写回/消息/执行接口全不开放 | f32 |
| 知识源一致性 | 单一权威知识库 | 存在两套制度知识源，章节号冲突，引用语义校验缺失 | 上线清单 D-04/D-05 |
| 授权确认人 | RBAC 名单明确 | 授权确认人清单缺失，人工复核有效性无法判定 | f42、r4 |
| 效果基线 | 有生产查询样本可做评测 | 仅 80 单 / 22% 虚构基线，无真实样本 | f12 |

**结论**：可比案例证明「RAG + 门禁 + 人工复核」这条技术路线在同类场景可行，但不构成本项目可行性证明。本项目的瓶颈是**字段/编号/授权/样本**四项前置条件，属于 G0 证据门禁，不是模型能力问题。
