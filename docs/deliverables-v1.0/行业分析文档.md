## 二、执行摘要

1. **总量温和、结构剧变**：2025 年人力资源服务业营收约 3.1 万亿元，同比 +3.7%，但灵活用工以 17.8% 的复合增速扩张，传统劳务派遣收缩约 40%。行业从「卖人头」向「卖调度能力」迁移，调度能力的核心是**记录一致性与可追溯**——恰是本项目痛点所在。
2. **合规是硬边界，不是加分项**：《劳务派遣暂行规定》第 3、4、5、7 条对岗位性质、10% 用工比例、2 年以上合同、派遣协议 13 项载明内容有强制要求；2025—2026 年多地公布超比例用工处罚案例。岗位性质、地点、人数、期限、工时、技能条件一旦被 AI 辅助结果影响，必须有人确认与全量留痕。
3. **标杆企业已把数字化投向标准化交付**：外服控股 2025 年营收 241.29 亿元，业务外包占 81.63%，研发投入 1.31 亿元（占营收 0.64%），「数字外服」结项后转向 AI 招聘智能体与国际业务平台。低毛利的外包主业决定了 AI 的价值首先在降低交付摩擦，而非替代人。
4. **技术路线已被验证，但门禁比模型更关键**：公开可比案例普遍采用 RAG + RBAC + 审计 + 人工复核，并设置可量化门禁（如 groundedness >90%、answer correctness ≥0.90、faithfulness ≥0.95）。行业报告同时指出仅 2.7% 的企业达到规模化 AI 应用、5.5% 能以可衡量业务成果证明价值——**评测与证据链是分水岭**。
5. **对本项目的结论**：优先补证据、字段契约与人工复核闭环，再谈自动化扩面；不把行业增速或虚构基线当作 ROI 输入；四来源中的 Industry 视角可由本文件补齐「公开事实」部分，但「本项目适用性验证」仍未完成。

1. 法规与处罚案例以政府官网原文为准（A 级）；

3. 行业规模数据必须同时标注口径与来源，冲突时并列保留，**不强行取平均或择一采信**（C 级）；

## 五、政策与合规底线（A 级来源）

| 条款 | 强制要求 | 对 AI 系统的含义 |
|---|---|---|
| 《劳务派遣暂行规定》第 3 条 | 仅限临时性（≤6 个月）、辅助性、替代性岗位；辅助性岗位须经职代会讨论、协商并公示 | 岗位性质字段不可由模型推断填充 |
| 第 4 条 | 被派遣劳动者数量 ≤ 用工总量 10% | 任何涉及人数与用工结构的辅助结果须人工确认 |
| 第 5 条 | 订立 2 年以上固定期限书面劳动合同 | 合同期限字段为法定要素 |
| 第 7 条 | 派遣协议须载明岗位名称与性质、地点、人数与期限、报酬、社保、工时休假等 13 项 | 与本项目「六项关键字段」高度重叠，须纳入字段契约 |
| 《劳动合同法》第 92 条 | 责令限期改正，逾期按每人 5000~10000 元罚款；派遣单位可被吊销许可证 | 错误传播到客户现场的代价可量化且不可逆 |

**公开执法案例**：2025 年四季度内蒙古某电力安装分公司派遣人员占用工总量 36.20%，被责令重签外包合同并整改；2026 年 4 月东莞某企业用工 989 人、使用派遣 165 人（超比例 67 人），逾期未整改到位仍超 41 人，被罚 20.5 万元；另有许可证到期未延续继续经营被罚 29.3 万元的案例。

**落到本项目的三条设计约束**：
- 试点只开放脱敏只读导出，写回 / 外部消息 / 执行接口不开放（项目 f32）；
- 不自动决定录用或派遣资格、不向真实人员发送安排、对外承诺由业务人员确认（f05、f52）；
- 每条结果关联来源与人工复核记录，审计能看到谁查过、用哪版、提了什么建议、谁确认（f42、f45）。

## 八、与本项目现状的对照

| 能力 | 行业可比实践 | 本项目现状 | 差距 / 风险 |
|---|---|---|---|
| 制度知识 RAG 问答 | 单一权威知识库 + 引用溯源 | 已实现混合检索与 SSE 流式；存在两套制度知识源，章节号冲突 | D-05 知识源未统一；D-04 引用编号可能「未越界但指错块」 |
| 权威性与拒答 | faithfulness ≥0.95 门禁、no-hallucination policy | 有拒答白名单与 30 条评测用例；缺语义级引用校验 | 需补语义校验与 golden dataset 回归门禁 |
| 身份与权限 | Entra ID / RBAC 按角色裁剪工具 | JWT + 租户隔离 + require_admin；Agent 9 工具按角色裁剪、状态机 + 一次性能力令牌 | 与行业实践对齐；限流仍为进程内存（D-03） |
| 人工复核与审计 | 全链路追踪 + 评测打标签 | 6 处人工确认 / 审核点、全量审计、规则预筛 suspected 必须人工定性 | 预筛漏「伪造发票」同义改写（D-01） |
| 评测与放行 | LLM-as-a-Judge 进 CI、阈值阻断 | 39 条量化用例 39/39 通过、build.sh 7/7；CI 跑全量自检 | 演示环境通过≠生产放行；12 项 P0 阻塞未关闭 |
| 模型与知识边界 | 私有化部署、知识不出域 | 归档 MVP 无密钥时降级 MockLLM（会回显提示词前 300 字，D-02） | 生产必须禁用 MockLLM 并重跑评测 |
| Agent 编排 | 多 Agent + 可观测 | 自建轻量 Harness（最多 5 轮、决策日志落表、3 条典型轨迹） | D-06 未接入主聊天链路 |

**结论**：本项目在「服务端硬门禁 + 人工复核 + 全量审计」上比多数公开案例更保守、也更贴合合规要求；短板集中在**知识源一致性、引用语义校验、生产级限流与回滚、以及真实样本基线**，这些都不是换模型能解决的。

## 九、对需求优先级的启示

沿用已交付《需求分析方案 v1.0》的四维评分（业务价值 / 证据强度 / 可拦截可恢复 / 成本友好度）与 P0 六项、P1 三项、P2 两项结论，行业视角补充三条判断：

1. **P0 应优先给「证据与字段契约」而非「生成能力」**。行业案例的失败大多来自知识库陈旧与来源不可追溯，不是模型不够强；G0 补证、统一关联编号、六字段契约、授权确认人清单必须先落地。
2. **把量化门禁写进验收，而不是写进宣传**。建议把「引用正确率、拒答正确率、越权拦截率、审计留痕完整率」做成 CI 阻断项，参考可比案例的阈值设计，但阈值须用本项目真实样本标定，不能直接照搬 0.90 / 0.95。
3. **报价与扩面分开决策**。行业增长数据不能替本项目证明收益；三档报价方案已明确低档按期权价值考核、中高档才按 ROI 考核，且 22% 虚构基线不得进入模型。
