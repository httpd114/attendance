## 4. 验收口径（决策者版本）

只看两条（f02）：

1. 30 个岗位是否**全部**列出硬条件和待确认项；
2. 变更是否有影响清单。

决策者本人明确指出**口径未定**：验收究竟看「重复核对次数下降」，还是看「异常拦截与交接一致率」？口径不定无法做试点决策。该问题须在 G0 门禁书面关闭。

## 5. 停止条件

- 试点范围扩到接待服务区以外，或异常复核需额外加人 → 四周与两名骨干的前提不成立，重新评估（f03）。
- 无法确认需求单版本或关键字段 → 进人工队列，必要时暂停（f44）。
- 只修模板不核对效果 → 不足以结束试点（f55）。

## 6. 决策者提出的待澄清问题（原文要点）

1. 验收看重复核对次数下降，还是异常拦截与交接一致率？
2. 试点覆盖哪些岗位、异常由谁复核、旧单如何作废？
3. 停止试点是触发即停，还是需质量负责人书面确认？结果用途何时定？
4. 成本核算只算试点直接投入，还是要把后续扩面预估成本一并列？
5. 首期优先验证「条件变更可识别」，还是「交接单与需求单一致」？
